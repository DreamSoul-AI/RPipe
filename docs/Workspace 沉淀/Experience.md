以下五项保留原提案细节和2026年11月2日整理时的状态，作为经验来源与候选，不代表当前workspace每条规则的采用状态。本次只确认新增的经验收集流程，不重定既有提案结论。


## （一）AGS-001 专项规范不能被共用概括豁免

**状态**：待讨论，已取得本项目偏差证据，拟修改既有条目。

**来源与问题**：共用正文第五章写“不强制测试框架、清单文件、目录镜像、计划名称或输出格式”，本仓又明确采用[《测试规范 代码》](https://dreamsoul.feishu.cn/docx/KE4IdW6EWoKdvExSkdvcjTJFnsf)。该规范第四章规定镜像目录与结果粒度。本项目把有用途的测试等同于落位合理，存在测试根归属、make 测试迁位和逐目标结果缺口。执行遗漏须整改，不以措辞歧义替代责任。

**拟替换文字**：

> 共用入口不另定项目布局或重复专项规则。任务已采用的专项规范，其适用要求仍须执行，不能因本文件未逐条复述或使用“不强制”的概括而豁免。冲突先核对象、范围、版本与用户确认，不由 Agent 静默选取较宽要求。

**验收与边界**：以本仓测试落位整改验证该表述能否指导实际决策；保留不适用项与依据。不得将所有项目强制改成 RPipe 的两柱或 pytest 布局。

**拟合并文字**：

> 开始时定位本次适用的规范正文及相关条款，交付前对照实际成果与证据核验。记录会影响采用的缺口、不适用依据及待确认项。读过入口、文件存在、检查通过或完成标记，不能单独证明满足规范。复用稳定且仍适用的来源，不要求小改动重读全部资料或重复填写完整清单。

## （四）AGS-004 用户确认机器相关路径与链接布局

**状态**：本项目已用合成输入完成Windows路径/链接及真实入口忽略验证，范围和前提见[四项整改验证](<../运行记录 Run Record/2026-11-02 四项整改验证.md>)。共用提案仍待跨项目验证和讨论。

**来源与问题**：数据、模型权重和大产出经常不能随 Git 迁移，用户明确要求中央外部位置与 symbolic link 访问方式。本项目当前输入文件链接、硬链接回退和 Windows 输出目录链接限制尚不能代表所有项目或后端。暂行规则和人工填写模板见[README 数据与大产出](../../README.md#数据模型与大产出暂行规范待实测)。

**拟合并文字**：

> 涉及大量数据、模型或产出时，首次使用、换机或路径变化须由用户确认实际输入、缓存、运行输出和证据位置，以及项目内访问入口和真实目标；已确认且稳定时复用。项目说明链接类型、忽略规则、可写范围和清理边界，核解析后的路径、消费者与实现支持，不能静默复制大文件、改变根或把链接当只读保护。机器路径在项目的用户本机记录中填写，不写死成跨项目默认值。

**验收与边界**：先在 RPipe 用独立合成文件验证链接/目标保全、权限与跨卷限制、忽略及监管；再在其他适用项目核可复用性。哪些场景使用目录 symbolic link、junction、文件链接或不设别名按项目确认，不能把本仓暂行实现限制写成跨项目禁令。原始输入、模型与可写产出分开，源码、配置和来源清单继续版本化。

## （五）AGS-005 按职责和接口核设计一致性

**状态**：待讨论。本项目两组依赖环已按职责拆开，模型冲突合同经用户确认后落实，分项及独立回归通过；不将本项目目录或全部无环约束直接推广到其他项目。

**来源与问题**：RPipe 两柱及唯一 write 的主要职责路径可对应，但包含函数内导入的静态图发现 data.factory/profile、algorithm 基类/工厂/实现的两组循环；模型 shape 解析行为与“冲突拒绝”的设计边界未完全校准。只有目录同名或禁止一条反向依赖的检查不够。

**拟合并文字**：

> 设计一致性按本次影响核职责、接口、状态归属、依赖与失败行为，不能只检查目录名、文件存在或一条导入关系。区分静态依赖、运行调用及资源持有，延迟导入不消除职责环。发现设计与实现或测试期望不一致时登记具体合同，先校准再调整，不用现有实现反证设计合理。

**验收与边界**：本项目两组环和模型冲突处理形成设计依据及回归，作为提案验证；具体模块拆合不进入共用正文，不要求所有依赖图绝对无环，由项目已确认合同判断。
