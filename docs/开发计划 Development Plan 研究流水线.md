## 2026年11月26日本地验证精简

用户要求缩短每次合并的 CPU 验证等待。本轮先交付本地结果，按 Markdown、科学组件及共享执行／配置的实际影响选择检查。保留原 core 与完整验证入口，新增合并离线批次；结果和适用范围见[测试说明](../tests/README.md#本地按影响选择)。

当前已实现本地选择预览、文档文件引用检查和现有执行器调用，已完成25项工具回归、796项科学组件场景及42项同清单耗时对比。随后已按授权修复取消读端瞬时冲突，2381项完整离线回归通过，1项既有静态豁免；TensorBoard真实读回也通过。原失败、环境差异和中断按原身份保留。最近文档 PR #266 的 CPU 工作流约12分钟，随后 dev 集成约13分钟，来自既有运行起止时间。审批额度故障解除后已取得步骤原件：最慢 Windows 任务安装100秒、core204秒、integration385秒，测试执行是主要成本。

用户随后授权自动 CI 的本地改稿。已保留全部 PR／push 触发与必需检查名称：文档 PR 只做标准库文档检查，科学组件按影响选择两组跨平台 CPU，公共合同与发布保留四组完整 CPU 及严格打包。dev 合并后的第二轮只有在最新成功 PR 回执、目标基线、文件树和选择范围一致时复用；直接 push、新基线、缺失或过期证据均恢复完整检查。详见[CI 选择规则](../tests/README.md#自动-ci-本地改稿)。

本地改稿已完成，现按进一步授权进入工作分支PR：从最新dev迁入本轮文件，不混入旧工作区的其他改动；核对真实CPU、打包、文档门和失败阻断，检查通过后合入dev，再下载回执核验第二轮复用。实际耗时回填本页及日期记录，保护规则保持原状。现有约27分钟是旧线上基线，新稿尚无线上提速实测。main、手动触发和发布验收保留完整检查。

记录见[本轮开发记录](<开发记录 Development Record/2026-11-26 本地验证范围精简.md>)与[运行记录](<运行记录 Run Record/2026-11-26 本地测试选择与耗时对比.md>)。

## 发布范围与验证

v0.5.1 汇集 v0.5.0 后的外部 data/output 入口配置、GitHub 文档整理及新研发约定，不承诺新增科学结论或下游兼容层。版本元数据与 CLI 一致，wheel／sdist 分别验证严格来源及 Toy/Stub 离线主流程；现有 CI 继续提供跨平台 CPU 和打包检查，保持既有失败与跳过语义。

另包含Windows取消收尾对实际worker身份的最小修复。原CI失败和本地反例分别保留，证据及归因限制见[运行记录](<运行记录 Run Record/2026-11-07 v0.5.1发布与取消收尾验证.md>)；任一新候选必需检查失败均阻断，不以其他平台通过替代。

本地检查覆盖 Markdown 解析、文件和章节链接、代码围栏保全、规范适配与必要版本回归。GitHub 实际显示与本地解析分别记录，不把静态通过写成逐页视觉验收。科学代码与协议保持原身份，无默认重跑要求。
