# 二、职责与实际收尾

无生产消费者的 data.prepare 和 io.kinds 退出，保留有用途的真实常量、数据 profile 和 Registry。make 对未知声明采用统一拒绝，不为 freeze 或 prepare_shared 维持专项兼容；capacity 生成声明中的旧键同步退出。Logger 旧事件别名删除，实际 checkpoint 事件直接使用 checkpoint.saved。Cancellation 无消费者的 requested 同义属性及 CLI study/run-one 同义命令退出，run 的发布语义和 launch 的执行语义分别保留。

CLI 的完整批次退出要求非空选择、完整返回、执行成功、质量非 False 和证据完整，保留各 Run 原始状态。执行域临时 SIGINT handler 只请求同一 Cancellation，结束恢复旧 handler；计划、读端和派生不由这个执行处理器接管。

科学进程不共享父进程的 threading.Event；取消通过明确 attempt 文件中绑定 request nonce、身份、attempt 的控制消息传递，ScienceContext 只接只读检查器。父进程核 owner 后才发送，按同一最终响应核验入口收尾，保科学首错及清理错误，未确认关闭时保权。合作等待与所属资源停止受清理时限和硬 deadline 约束，不延长监管上限。Windows 的协调者和科学 worker 均使用独立进程组，worker 临时屏蔽直接 SIGINT 并恢复；父进程是取消信号的唯一转译点。

安装 smoke 显式绑定实际制品与新 venv，核导入、metadata、console、RECORD 和本地 archive 来源哈希；子命令清外来 Python 路径。CI 的实际调用同步传 --artifact，证据归档及失败保留流程不变。两种实际构建/安装在新外部副本和各自新环境执行，未安装构建前端或修改全局依赖；共享现有科学依赖与纯净依赖解析分开报告。

# 三、验证中发现的问题与处理

分组回归保留两项原始失败。新 Logger 测试曾错误期待非结构化事件被改名，修正测试为原本 logging.unstructured_record 行为，未恢复旧别名。Windows 真实连续质量门测试则在进度读取时得到没有 winerror 的 PermissionError；保留原反例、原质量 False 和未派发后续项的证据，没有放宽 trigger 判据。

两个独立并发探针复现读端 EACCES；第二个在清空 UCRT 错误后立即取得原生码，全部失败为共享冲突 32。原回归未采此码，不追补为已确定 32。原子替换保证完整文件的发布点，不能保证 Windows 所有读句柄均可同时打开。通用调研补核官方机制后，System 只提供当前线程原生文件错误原语，Flow 在观察本次 progress 时最多三次、每次不超过5毫秒地重试已确定的32/33；永久权限、格式、身份及不明确错误立即失败，重试前后核取消和期限，不用旧观察放行后续 Run。

最小修复不泛化为所有文件的重试策略，不修改 artifact 原子写端或研究门。原生独占句柄32与目录访问5有实际对照，窄回归另核耗尽、永久拒绝、取消、期限及CRT清空失败；完整结果从运行记录追溯。
