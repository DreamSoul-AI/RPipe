# 二、生命周期与阶段职责归位

| **实际模块** | **本批落实** |
| --- | --- |
| flow.context | 承接请求预算、取消、RunReport、RunContext、ScienceContext、派生上下文与有限 JSON 草稿约束；不读写、不加载科学实现或启动进程 |
| flow.run | 统一准入、执行权、初始与终态事实、首错、取消、收尾及发布准许；科学资源不在持权者中装配 |
| flow.worker | 负责自身请求、科学子进程、等待/回收及响应核验；无 owner 交接，不发布科学结果 |
| flow.stages | prepare/execute/collect/summarize 直接承接已有真实装配和观测；write 是正式 result 与执行事实的唯一写操作；process 只在发布后消费已存记录 |
| flow.process | 分开 Run 与 Study 派生作用域，明确清单、保存结果和派生目标，不复用关闭后的模型、数据、Tracker 或 System |
| flow.supervision | 普通 launch 与资源监管都调用同一 run；未知、拒绝、不完整或失败停止后续派发，监管不另建生命周期 |
| artifact.io | 承接持久化执行事实的纯投影与原有路径/原子/排他原语，读端不反向依赖 flow |

# 三、持权与唯一 write

持权前 busy、来源/配置失配或不支持的预算返回 rejected 请求报告，没有 attempt，不向目标 Run 写失败事实。来源在准入、派发及科学入口再次核验；有效配置在阶段、收尾和成功定稿前检查，使用严格 JSON 比较区分 true、1 和 1.0。已有 config 的 Run 准入及 make 发布同步拒绝这种类型漂移，不改其原字节。

请求与响应绑定 schema、nonce、来源/配置身份、attempt 和日志请求标识。科学进程只交出草稿及实际环境、清理和释放观察，关闭资源后再次核配置；持权者核响应、进程退出及资源关闭后才允许 stages.write 保存科学成功。结果后 process 使用新的纯派生上下文，派生异常不改科学结果。

已核验且明确关闭的科学失败可以 failed；首错或非零退出本身不代替资源观察。丢响应、核验失败或资源未确认关闭保持 unknown 和执行权，禁止科学成功、新 owner 及后续派发。当前 owner 可以经同一 write 追加自己的 unknown 事实，换 owner 后的旧执行者不能污染 peer。

修复 Ownership.release 在删除 owner.json 后 rmdir 失败丢失凭据的边界：仅在设备/文件身份仍为原目录时，以排他新建恢复原 token 字节，再抛原始失败；已有 peer owner 或替换目录不得覆盖。这样未确认释放时仍能核明当前所属并保存本次 unknown，不通过猜测重建所有权。

# 四、失败保全与调用核对

科学首错与清理新错分列；取消异常附带的 cleanup_errors 进入正式清理观察，不能仅保留为异常 cause 后误报取消完成。cleanup-only 的已核验响应不制造 ChildExit 首错。清理诊断在 worker-output、正式执行事实和返回报告前净化，包含非法条目/序列的反例不泄露原异常正文或私人路径。

科学 Logger 的输出或关闭失败不阻断回传响应，也不掩盖科学首错；父子使用同一请求身份，已由科学进程记录的首错/清理不重复记。write、process 与 closing 的日志阶段明确，日志异常不能改签此前科学结果。

关联迁位同时修复原 api.process 调用缺少 load_config 导入的断点。Study 汇总在 aggregate 后、写派生物前再次核来源；汇总期间来源失配时保全原有效汇总和无关文件，不把读端捕获的 invalid 行当作允许覆盖依据。监管进度接受 rejected 请求报告并正常停止，保留真实拒绝原因。

测试从旧执行接口迁到 flow 的实际生命周期/context/process/worker，科学动作使用测试 stub，但请求响应、阶段门、收尾、持权和唯一 write 走真实实现。子进程专属反例仍启动受控真实进程，不以 inline fixture 代替全部进程验证。前次记录的已删除源码或迁位测试引用固定到本批基线，保留历史身份。
