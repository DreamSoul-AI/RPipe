# 二、按设计落实的职责

| **职责** | **实际落点与边界** |
| --- | --- |
| 有效条件与身份 | [control.py](../../src/rpipe/structure/control.py) 承接配置类型、覆盖、有限 JSON、内容身份和 RunSpec；不读写、resolve 路径或导入科学实现。保留已核验的有效配置优先级及内容 ID |
| 读取、展开与发布 | [make.py](../../src/rpipe/structure/make.py) 分开只读 plan、纯 expand 与显式 publish；展开因素×seed，明确 train 依赖，不执行 recipe 或猜 checkpoint 目录 |
| 存取及所有权原语 | [artifact/io.py](../../src/rpipe/structure/artifact/io.py) 承接路径保护、原子文件、锁、执行事实读取及现有共享输入存取；保留原错误处理，io 不反向依赖 provenance |
| 来源与观察 | [artifact/provenance.py](../../src/rpipe/structure/artifact/provenance.py) 承接源码和显式输入摘要、环境观察、来源准入；显式调用才扫描，不导入科学实现 |

RunSpec 的 experiment 由有效条件、来源与 version 派生，不再接受被忽略的构造参数。纯规格只核绝对路径及父目录跳转等词法条件；实际路径解析、输出与源码/输入隔离在显式读取或发布准入完成。来源摘要与科学配置 ID 分开，移动源码不为旧实测换身份。

# 三、发布合同与失败保全

publish 在写入前核同一来源/version/输出域、重复身份、依赖缺失和环、父项 train 模式及同 seed 同有效训练条件。来源、受保护路径、已有配置、结果、execution 和 index 都进入准入；旧来源或旧格式的同 version 计划明确拒绝，不能对旧执行事实重新签名。

持有 Study 规划锁，再按稳定 ID 顺序取得全部目标 Run 所有权，直到 index 最后提交才释放。锁内重核来源和既有事实；完整配置先写，重复发布保留已有配置字节；schema 3 index 将来源文件清单、digest、version 与 Experiment/Run 关系放进同一原子记录，避免两个独立可变文件错配。

这不是整个输出树事务。失败可留下尚未被 index 引用的完整新配置，但原有效 index、已有配置、结果、执行事实及无关 Run 保全；不递归回滚或删除归属不明的文件。原子存取与共享输入逻辑迁位保留原处理，未以清理为由删减保护。
