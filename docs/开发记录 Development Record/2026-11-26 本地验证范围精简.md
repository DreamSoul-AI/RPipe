## 取消请求读取修复

用户随后授权定位取消读取PermissionError并补齐完整回归。真实Windows CreateFileW独占句柄可稳定触发该故障，句柄释放后原实现仍直接报错。首次只按Win32共享错误码重试的修复未通过真实句柄反例，Python文件打开实际可只留下errno=13，winerror为空。已在取消标记的私有读端同时覆盖这一Windows路径，最多六次、间隔10毫秒。明确的其他错误码保持直接失败，持续冲突在界内抛原异常，成功后沿用request、identity、attempt及schema校验。

反例先于源码修改执行，原实现5项失败、2项通过。补齐修复后worker与真实取消47项检查通过，包含真实句柄释放后协作取消、持续冲突、普通权限拒绝及原有终态和所属资源检查。最初完整回归提前启动，后因真实句柄反例尚未通过而仅停止本次已核验进程树，原件保留。最终回归固定修复后的src与tests内容哈希执行。

历史原失败只有PermissionError及调用链，缺少底层错误码和锁持有者。真实句柄反例确认了当前读端的处理缺口，历史该次错误的具体持有者仍未取得。

## 自动 CI 本地改稿

用户确认减少重复检查需要先验证复用条件，随后授权落实本地 workflow 与选择策略。新增 `tests/ci.py`，两个既有工作流各自先选择范围，再执行 CPU／打包，最后由保留原名称的必需汇总门核验结果。plan任务的只读contents、actions、pull-requests权限用于核验关联PR、运行与小型成功回执，其余任务仅保留contents读取，不修改保护规则或远端状态。

纯 Markdown 不安装业务依赖或执行打包；科学组件使用既有影响选择和两组交叉平台／Python 组合，src 改动仍做两平台严格包验证。共享边界、配置、workflow、未知范围、main 及手动触发执行完整矩阵。完整 CPU 合并成一次离线收集，单独 TensorBoard 读回保留。现有 wheel／sdist 来源哈希与安装合同保持。

dev push 继续触发。仅在实际合并提交关联已合并 PR，且其最新成功运行的回执同时匹配目标基线、文件树、head、选择指纹和运行身份时复用。每种工作流单独核验，缺少一种证据只允许另一种复用。直接 push 或核验不成立回到完整检查，最新失败不回退旧成功。PR 测试提交和最终提交可以 SHA 不同，证据中保留各自身份。

工作流不使用 paths 过滤，避免必需检查缺失。汇总门在上游失败／跳过后仍执行，只接受计划内成功或明确未选任务的 skipped。GitHub [任务依赖说明](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-jobs)与[artifact 下载接口](https://docs.github.com/en/rest/actions/artifacts)分别支撑调度和回执下载设计；本地验证不代替远端调度验收。
