# 一、问题、假设与文献依据
研究对象是小型本机研究流水线的执行与证据合同。目标不是证明通用平台优越，而是判断真实失败场景下，结果能否保持来源准确、失败可见、成功不被破坏。背景、替代路线及阅读深度见 [通用调研](<研究流水线 通用调研.md>)，工程责任和测试设计见 [架构设计](<研究流水线 架构设计.md>)。

| **问题** | **可反驳的假设** | **反例与改变判断的条件** |
| --- | --- | --- |
| RQ1：冻结拒绝或后处理失败会损伤旧成功吗？ | H1：已有成功的科学结果字节保持，失败另存执行事实 | 注入失败后旧成功被覆盖、误标失败或新结果混入，立即反驳 |
| RQ2：读取缺失/损坏可选元数据会伪造或污染比较吗？ | H2：保留有效 peer，明确缺失与错误，不填虚构值，不取得执行权 | peer消失、缺失被记零或读取触发重跑，立即反驳 |
| RQ3：发布中断会出现半文件或清理别人的结果吗？ | H3：正式文件为旧完整值或新完整值，清理仅限本次拥有的临时对象 | 任一损坏正式值或删除无关文件，立即反驳 |
| RQ4：流程变化是否保留已声明科学行为？ | H4：同一有效条件下，配对轨迹、状态与自身best评测满足预定容差 | 数值/状态超过容差，先排查适配与环境；不能借退出成功放行 |

Pineau等复现工作只支持报告与独立验证职责，PyTorch文档限定版本/设备/随机性条件，MLflow/Snakemake是外部路线候选。没有同协议外部实测，尚不能宣称新颖性或更快、更可靠。论文原文补读与比较设计先于这类结论，不因文档中列了候选就安装、训练或启动服务。

# 二、数据、模型、算法和指标
## （一）合同实验
数据为独立临时目录中的小 JSON/YAML/文本、合成路径及必要的小 CPU Tensor。覆盖缺失、损坏、错误类型、写入/替换异常、读取期间忙状态、失败清理与重复调用。每个失败案例先记录期望和实际，修复后验证同一入口；不把生产 Run 当可清理 fixture。

模型为可确定退出和输出的假载荷，不使用下载权重或训练数据。算法是声明展开、调度、执行、发布与读取的真实调用链。指标为执行权唯一性、旧成功哈希、正式文件可解析性、peer保留、异常类型、最终状态和副作用计数。零外部调用、零额外写盘等断言仅用于明确要求无副作用的路径。

## （二）科学行为对照的共同条件
数据集为 MNIST（train60000/test10000）与 CIFAR10（train50000/test10000），任务均为10类分类。原始16文件哈希表是 [EXPECTED_DATA.json](../studies/main_exp/docs/EXPECTED_DATA.json)，只记录身份，不是数据本身或重新下载授权。固定参考数值是 [REFERENCE_CURVES.json](../studies/main_exp/docs/REFERENCE_CURVES.json)，属于科学输入，不是运行报告。

模型逐项列明：
- MNIST/CIFAR10 的 linear：历史自有 PyTorch 实现，结构由固定来源代码决定；本轮未重新统计参数量
- MNIST/CIFAR10 的 mlp：同上，隐藏层等参数沿用相应固定配方；本轮未重新统计参数量
- MNIST/CIFAR10 的 cnn：同上；本轮未重新统计参数量
- MNIST/CIFAR10 的 resnet18：历史适配实现，不把名称等同于任意 torchvision 默认值；本轮未重新统计参数量

参数规模和具体 Torch/CUDA/设备型号若进入新实验，必须在启动前从实际构造与环境记录补齐，不能由模型名推断。历史 CUDA 数字见通用调研中的唯一摘要，本轮未访问 GPU。

配对比较固定原始数据、预处理与增强、batch顺序、RNG状态、初始化、优化器、scheduler、精度及设备后端。记录两侧实际提交、依赖和控制开关，不以同seed代替条件对齐。checkpoint比较参数、优化器、scheduler、步数和best选择状态，独立eval只读自己的best，不能借另一侧或别的seed替代。

## （二）main_probe：数值配对短探针
现有声明在 [study.yaml](../studies/main_probe/study.yaml)，机器配方在 [experiment_config.yaml](../studies/main_probe/experiment_config.yaml)。历史源为 `98648f3a5c7db7dccf3ca806410d5b6fdee9484c`，新侧为该次真实待测提交。两数据集 × 四模型 × seed0，共8个配对Run，每侧60次optimizer更新，第30/60步完整评测test10000。

| **条件** | **固定值** |
| --- | --- |
| 数据 | batch250，test_batch_ratio4，pin_memory true，workers0，augment true |
| 算法 | SGD，lr0.1，momentum0.9，nesterov true，weight_decay0.0005，不裁剪梯度 |

| 判据 | 浮点Tensor atol1e-6、rtol1e-5，Loss绝对差≤1e-6，整数/计数严格相等；同时检查RNG、采样、优化器、scheduler和best状态 |

## （三）main_exp：历史图像协议
现有声明在 [study.yaml](../studies/main_exp/study.yaml)，机器配方在 [experiment_config.yaml](../studies/main_exp/experiment_config.yaml)。基准配方和原PNG来自 `4ccb28d0496110253e9f8e3f3df658853f07996b`。两数据集 × 四模型 × seed0/1/2/3，32train及其32个自身best独立eval，不能把train/eval因素误计成64条训练。

| **条件** | **固定值** |
| --- | --- |
| 数据 | batch250，test_batch_ratio1，pin_memory true，workers0，历史增强与模型适配不变 |
| 算法 | SGD，lr0.01，momentum0.9，nesterov true，weight_decay0.0005，max_grad_norm1 |
| 训练与学习率 | 80000次optimizer更新，cosine T_max80000、eta_min0 |
| 评测与保存 | 每200步完整test10000，共400点；latest每2000步，test/Accuracy最大者为各自best |
| 设备与精度 | 历史协议CUDA，确定性控制，两类TF32均false；历史预算4831838208字节；非本轮资源授权 |
| 前置数值门 | 两数据集×四模型×seed0，各600步/每200步评测的固定原实现配对，对齐来源与精度后判断 |

PNG没有完整历史指标。参考数字是图像估读：MNIST误差约±0.05个百分点，CIFAR10约±0.20个百分点；横向虚线取点也有偏移。首槽对应step200，不是初始化；固定锚点槽50/150/200/250/300/350/399对应step10200/30200/40200/50200/60200/70200/80000。原始固定数值保留JSON，不由新结果重估门限。

| **四seed mean与参考图像比较，单位为Accuracy百分点** | **MNIST** | **CIFAR10** |
| --- | ---: | ---: |
| step80000末点绝对差 | ≤0.25 | ≤1.00 |
| 末50点均值绝对差 | ≤0.25 | ≤1.00 |
| 固定锚点MAE | ≤0.25 | ≤1.00 |
| 固定锚点最大绝对差 | ≤0.60 | ≤2.00 |
| 新均值曲线末50点时间std，ddof0 | ≤0.15 | ≤0.50 |

每格必须32条训练对应的四seed齐全、每条400点，每点样本数10000，按真实step对齐，跨seed std用ddof0。两数据集的模型末段均值顺序均须resnet18>cnn>mlp>linear。时间std与跨seed std不是同一指标，阴影不是置信区间。全部执行和数值门都满足，才可称“按固定口径接近历史图像”，仍不能称恢复了原历史环境或逐位轨迹。

一次实现的完整矩阵预算为2560000次optimizer更新、640000000次训练样本处理、12800次完整曲线test评测和128000000次test样本处理，另外32个best独立eval处理320000样本。再运行旧实现需另计，不用短前缀承诺墙钟时间。当前配方 `resume:false`，历史两条中断训练以新身份从step0重跑，不能伪造连续launch或任意行恢复。

## （三）工作量与资源上限提案
E3 既定工作量为八格配对、每侧60次更新，共960次 optimizer 更新和240000个训练样本处理。第30/60步完整 test 共320000个样本处理，两侧自身 best 独立 eval 再处理160000个样本。数据与计数按实际观察核对，以上不是运行成功或耗时预测。

下表数值仅为后续资源讨论的初始上限提案，尚未测量校准或批准。历史配置中的5 GiB 显存字段继续保留历史身份，不能充当本轮实际准入或硬限。

| **资源** | **待确认提案与约束** |
| --- | --- |

| 墙钟 | 每格最多15分钟，全批含准备最多120分钟。执行前据实际设备和监管能力确认，不满足时回到计划，不缩小数据或放宽门限 |

| 外部存储 | 本批新增输出最多20 GiB，启动前确认可用空间。超过上限保留已有证据并停止新派发，不删除无关输入、旧 Run 或别人的文件 |

Windows 含 Study 扩展时不能借 CLI timeout 声称后代硬停止。执行前明确监管的进程范围、观测频率、期限、停止办法和 unknown 的处置，只处理自有资源。无法实现所需监管时不启动该批次，先解决能力与授权缺口。
