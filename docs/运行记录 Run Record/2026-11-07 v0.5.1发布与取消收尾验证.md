## 本地诊断与确定性反例

本机Windows/Python3.13.9用统一入口运行原四种真实取消情景。首次子进程出现Anaconda DLL加载失败，退出码3228369022，四项失败，保留在 `cancellation-local-tests/` 及 `cancellation-local-temp/`；这与远端断言失败不同，不混为同一反例。

采用已知任务局部DLL profile及新的独立目录后，原四项通过，约9秒。profile只通过本任务环境生效，不修改全局环境。诊断插件在测试结束后保存本次合成Run的执行及worker记录，不改变运行输入或预算。

沿调用链另确认一个职责不一致：计算阶段同时检查启动进程和已准入的实际worker，取消收尾却只检查启动进程；在启动器先退出、实际worker仍处于结束窗口时，会跳过协作等待并过早按残留后代处理。确定性回归在旧实现上失败，取消请求没有发出；反例证据见 `actual-worker-before-corrected/`。更早一次测试替身未完整接入的诊断也保留，不将其单独作为有效反例。

修复只复用实际worker存活判断，保持既有cleanup_seconds和硬截止，不放宽失败断言、不把未知资源标为已释放。真实取消断言追加RunReport，今后若再失败可以定位首错与清理错误。该修复覆盖已确认的生命周期缺口，不能据此唯一归因原CI失败。
